# 모바일 청첩장 — 디자인·구현 규칙

이 저장소를 수정할 때 항상 지키는 규칙입니다. 규칙을 바꿔야 할 것 같으면 먼저 사용자에게 확인하세요.

## 폰트
모든 글꼴은 셀프호스팅합니다. 기기 기본 글꼴에 맡기면 PC·일부 안드로이드에서 맑은 고딕이나 사용자가 설정한 글꼴로 바뀌어 촌스럽게 보이기 때문입니다.

| 용도 | 글꼴 | 적용 방법 |
|---|---|---|
| 읽는 글: 섹션 제목·인사말·혼주·커버 일시/장소·예식 일시 문장·예식장명·안내 문구 | Noto Serif KR (명조) | `css/style.css` 상단 그룹 셀렉터에 클래스 추가 → `var(--font-serif)` |
| 성함·큰 숫자 (D-day, 달력 큰 날짜) | Noto Serif KR 600 | 해당 규칙에서 `font-family: var(--font-serif)` |
| 작은 UI 글자: 버튼·계좌번호·연락처·달력 숫자·교통 안내·토스트·라벨 | Pretendard Variable | body 기본값 `var(--font)` — 따로 지정하지 않음 |
| 영문 스크립트 섹션 제목 (Invitation / Location / Date …) | Yellowtail | `.eyebrow` → `var(--font-script)` |
| 커버 손글씨 (We're getting married) | Pinyon Script | 폰트 파일 없음. `scripts/make-handwriting.mjs` 로 SVG 윤곽 생성 |

- 새 글꼴 패밀리를 추가하지 않습니다. 필요해 보이면 비교 시안을 보여주고 사용자에게 묻습니다.
- 외부 CDN 폰트 `<link>` 를 쓰지 않습니다. `node scripts/fetch-fonts.mjs` 로 `assets/fonts/` + `css/fonts.css` 를 생성하고, `css/fonts.css` 는 직접 고치지 않습니다.
- Noto Serif KR 은 400/600 만 있습니다. 명조에 500/700 을 지정하지 마세요 (각각 400/600 으로 보임).
- 명조 본문은 획이 가늘어 `var(--ink)` 색을 유지합니다. 연한 회색(`--ink-faint`)을 명조 본문에 쓰지 마세요.
- 한국어 본문은 최소 14px(0.875rem)입니다. 섹션 제목(`.section-title`) 자간은 0.08em 입니다.
- 인사말(`.greeting-body`)은 320px 화면에서 가장 긴 줄이 한 줄에 들어가야 합니다. 현재 22자 = 260px, 가용 폭 264px. 문구를 바꾸면 다시 측정하세요.

## 색
- `:root` 토큰만 씁니다. 포인트는 버건디 `--accent #701018` (종이 청첩장 색)입니다. 새 색은 토큰으로 추가하고 흰 배경 대비 4.5:1 이상이어야 합니다.
- 라이트 모드 고정입니다(`color-scheme: light`). 다크 모드 스타일은 만들지 않습니다.

## 레이아웃 · 스크롤 (카카오톡 인앱 출렁임 방지)
- 모바일 우선 320~480px, 480px 초과는 가운데 카드입니다. 가로 스크롤이 생기면 안 됩니다.
- `vh`/`svh`/`dvh` 등 뷰포트 높이 단위와 `innerHeight`·`screen.height` 를 레이아웃에 쓰지 않습니다. 인앱 툴바가 나타나고 사라질 때마다 값이 바뀌어 화면이 출렁이거나, 처음 그린 크기가 최종 크기가 아니게 됩니다.
  - 커버 상자는 **기기 화면 비율 19.5:9**(`css/style.css .cover-photo`, `aspect-ratio: 9 / 19.5`, 390px 폰에서 844px)로 너비에서 정해지고, 사진은 `object-fit: cover` + `object-position: right` 로 왼쪽이 잘립니다. 사파리 26 은 반투명 하단 주소창 뒤까지 그려서 보이는 높이가 약 797px 라 그보다 길어야 아래 여백이 없습니다(사용자 캡처). **카카오톡 iOS 만 16:9**(`html.in-kakao-ios`, `<head>` 가 UA `KAKAOTALK` + iPhone 으로 붙임): 위아래 바가 약 195px 라 보이는 높이가 649px 뿐이어서 844px 면 얼굴이 아래 1/3 에 깔립니다(사용자 캡처). 같은 폰인데 브라우저마다 보이는 높이가 23% 달라 비율 하나로는 못 맞춥니다. UA 는 측정이 아니라 고정 사실이라 첫 그리기부터 최종 크기입니다. 화면 높이를 재는 스크립트는 없습니다. PC(`hover: hover`)만 `100vh` 입니다.
    - 이유: 카카오톡 인앱은 페이지가 뜬 **뒤에** 하단 툴바를 꺼내 화면 높이가 줄어듭니다. 높이에 맞추면 어떤 방법을 써도 커졌다 작아지거나(사용자가 두 번 겪음), 사진을 숨겼다 보여 주거나(갈색 화면, 사용자 불만), 아래가 가립니다. 너비는 툴바와 무관해서 처음부터 최종 크기입니다. 이 셋 중 어느 것도 다시 시도하지 마세요.
    - 거쳐 온 길(2026-10-13): 너비 × 1.6(매직 넘버, 사용자가 고정값 싫어함) → 사진 고유 비율 2:3 로 자르지 않기(사진 아래 여백이 생겨 사용자가 매우 싫어함) → 폰 화면 비율로 꽉 채우고 왼쪽 자르기(사용자: 왼쪽 잘려도 되니 맞춰라) → 20:9(기기 화면 비율)는 카카오톡 툴바만큼 보이는 영역이 짧아 얼굴이 아래 1/3 에 깔림(사용자 캡처) → 16:9 는 사파리 26 에서 주소창 뒤 ~100px 가 비어 보임(사용자 캡처) → 기본 19.5:9 + 카카오톡 iOS 만 16:9. 사진 전체를 보여 주는 것보다 **아래 여백 없는 것**이, 꽉 채우는 것보다 **얼굴이 가운데 오는 것**이 우선입니다.
    - 사진이 받아지기 전 바탕은 24px 축소본(base64)입니다. `node scripts/optimize-images.mjs` 가 `style.css` 에 넣습니다. 커버 사진을 바꾸면 꼭 다시 실행하세요.
    - 폰에서 크기 문제를 확인할 때는 주소에 `?debug` 를 붙여 열고 캡처를 받습니다. 창 크기 변화 기록이 화면 위에 표시됩니다.
  - 손글씨 위치는 사진 높이 기준입니다(`.cover-script { top: 17% }`, 위쪽 계단 자리).
    - 손글씨는 두 사람 얼굴(사진 높이 절반쯤)을 덮으면 안 됩니다(사용자 요청). 사용자가 아래쪽 대신 위쪽 계단 자리를 골랐습니다.
- 커버 아래 이름·일시(`.cover-text`)는 처음부터 보입니다. 예전엔 손글씨가 끝날 때까지 숨겼는데(`hw-pending`), 긴 화면에선 사진 아래가 몇 초간 빈 띠로 보여서 없앴습니다(2026-10-13). 손글씨 애니메이션과 스크롤 잠금은 그대로입니다.
- 커버 사진 위 글씨·버튼은 사진 아래쪽 25% 에 두지 않습니다. 인앱 하단 툴바(카카오톡 iOS ≈ 78pt)가 커버 위에 겹칠 수 있습니다.
- 애니메이션은 `transform`/`opacity` 만 씁니다. `box-shadow`·`height` 등 레이아웃/페인트 속성은 애니메이션하지 않습니다.
- 지도처럼 터치 스크롤을 가로채는 요소는 탭해야 활성화되는 veil 패턴으로 만듭니다(`#map-tap-veil`).
- 첫 화면 손글씨가 써지는 동안에는 스크롤을 잠급니다(`html.is-locked`). 탭하면 건너뛰고, 7초 뒤에는 잠금이 무조건 풀립니다.
- 스크롤 잠금(`overflow:hidden`)을 켜고 끌 때 PC 에서 스크롤바가 사라졌다 생기며 화면이 옆으로 튀지 않게, `html` 의 `scrollbar-gutter: stable` 을 유지합니다.
- 모달 대신 인라인 아코디언(`<details class="fold">`)을 씁니다.
- 갤러리 라이트박스(`#lightbox`)는 사진을 **화면에 꽉 채우고 확대는 막습니다**(사용자 요청 2026-10-27). `.lb-img` 는 `position:fixed; inset:0` 상자의 100%×100% 에 `object-fit: contain`(자르지 않고 가로 끝까지, 여백·둥근 모서리 없음, vh 미사용). 확대 금지는 `.lightbox { touch-action: none }` + `main.js` 의 두 손가락 touchstart·모든 touchmove·iOS `gesture*` preventDefault 로 이중 처리합니다(iOS 사파리는 touch-action 만으론 핀치를 못 막을 수 있음). 한 손가락 touchstart 는 막지 않습니다(막으면 버튼 click 이 안 생김).
  - 위아래 여백(2:3 사진 vs 9:19.5 화면)은 **같은 사진을 블러로 깔아 채웁니다**(`.lb-bg`, `filter: blur(20px) brightness(0.5)`, `object-fit: cover`, `z-index:-1`, `scale(1.15)`). 사용자가 A 검은 여백 / B 블러 배경 / C 잘라서 채우기 비교 시안에서 B 를 골랐습니다(2026-10-28). C(잘라 채우기)는 사진마다 잘리는 양이 15~22% 로 달라 거절. 사진은 절대 자르지 않습니다. 카카오톡 iOS 인앱은 보이는 높이가 짧아 여백이 사파리보다 훨씬 작게 보입니다.
- 모션 줄이기(`prefers-reduced-motion`)와 JS 꺼짐 환경에서도 내용이 전부 보여야 합니다(점진적 향상).

## 콘텐츠
- 문구·연락처·계좌·예식 정보는 `js/config.js` 에서만 바꿉니다. 기준은 종이 청첩장(`청첩장.pdf`)입니다.
- 방명록·참석 여부(RSVP)·공유 섹션은 넣지 않습니다 (사용자 결정).
- `assets/img/cover.jpg` 는 웨딩 사진입니다(원본 `image/01-cover.jpg` — 나무 계단 위 두 사람, 2026-10-13 사용자 제공). `node scripts/optimize-images.mjs` 로 커버(가로 1600px)와 카톡 미리보기 `og-image.jpg`(1200×630)를 같이 만듭니다.
  - 폰에선 사진 왼쪽(난간 쪽)이 잘리고(`object-position: right`) 두 사람이 가운데쯤 옵니다. 사진을 바꾸면 `object-position` 을 다시 맞춥니다.
  - 카톡 미리보기에는 두 사람 얼굴이 보여야 합니다(사용자 요청). 자동 크롭은 계단만 골라서, `optimize-images.mjs` 의 `OG_CROP` 으로 얼굴이 가운데 오게 직접 자릅니다. 카톡이 가운데를 정사각형으로 잘라도 얼굴이 남아야 합니다.
  - 갤러리 가로 사진은 `is-wide` 클래스로 2칸을 차지하게 합니다(사용자 요청, 2026-10-15). 새 가로 사진을 넣으면 index.html 의 해당 버튼에 `is-wide` 를 붙입니다.
  - 갤러리(`#gallery`)는 사용자 참고 시안대로 3열 정사각 썸네일, 카드 폭 끝까지, 간격 2px 입니다. 9장 초과분은 "더보기" 뒤로 접습니다(JS 꺼짐이면 전부 보임). 사진은 `image/` 의 커버 다음 파일들 → `gallery-NN.jpg`(긴 변 1440px). 사용자가 2026-10-14 웨딩 사진 3장을 넣으라고 해서 공개 저장소에 올렸습니다.
  - 촬영 전 임시 **종이 커버**(`scripts/make-cover-art.mjs` + `.cover--paper`)는 되돌릴 때만 씁니다. 그 스크립트는 `cover.jpg` 를 덮어씁니다. 종이 커버는 올리브 가지가 위쪽에 있어서 되돌리면 손글씨도 아래쪽으로 옮겨야 합니다.
- 배경음악 `assets/audio/bgm.mp3` 는 Pixabay 「Christmas piano ~カノン~」(pianocafe_Kumi)입니다. Pixabay Content License 라서 무료이고 출처 표기가 필요 없습니다. 사용자가 "채플 앳 청담·연말·클래식" 분위기로 고르라고 해서 골랐습니다. 직접 합성한 오르골 곡은 사용자가 별로라고 해서 버렸습니다.
  - 다른 음원으로 바꿀 때도 출처 표기 없이 쓸 수 있는 것(Pixabay·퍼블릭 도메인)만 씁니다.
  - 받은 파일은 `node scripts/prepare-bgm.mjs <파일>` 로 손질합니다(앞뒤 무음 정리, 128kbps). 원본은 저장소에 넣지 않습니다.
  - pixabay.com 은 자동 다운로드(curl)와 앱 내 브라우저 접속이 막혀 있습니다. 그래서 사용자가 직접 받아 `D:\김담영\mobile-invitation\` 에 넣어 줍니다.
- 공개 저장소라서 올리는 사진·음원은 모두 공개되고, git 기록에도 남습니다. 개인 사진(커플 사진 등)은 사용자가 명시적으로 원할 때만 올립니다. 예전 커플 사진은 사용자 요청으로 기록에서까지 지웠습니다(2026-10-02).

## 검증
- 수정 후 320 / 360 / 375 / 412px 폭에서 확인합니다: 가로 넘침 없음, 의도치 않은 줄바꿈 없음, 콘솔 에러 없음, 폰트 로드(Noto Serif KR · Pretendard Variable · Yellowtail).

## 작업 방식
- 페이지 HTML 자체도 GitHub Pages 가 10분 캐시합니다(`max-age=600`). 푸시 직후 폰에서 확인할 때는 주소에 처음 쓰는 쿼리(예: `?debug=3`)를 붙여 열어야 새 버전이 보입니다. 사용자에게 테스트를 부탁할 때 이걸 같이 알려 줍니다.
- 카카오톡 인앱 브라우저는 열리는 순간 예전에 저장해 둔 화면 스냅샷을 잠깐 보여 줍니다. 사용자가 "처음엔 다른 모양이었다가 바뀐다"고 하면 먼저 카카오톡 캐시 데이터 삭제 후 새 쿼리로 다시 보게 합니다(2026-10-14 확인: 기록상 페이지는 한 번만 그렸고 캐시 삭제로 해결). 확인 도구: `?debug` 화면의 `--- 지난 기록 ---`(디버그 없이 연 기록도 남음).
- 커밋 전에 항상 `node scripts/bump-assets.mjs` 를 실행합니다. `index.html` 의 CSS·JS·커버 사진·OG 사진 주소와 `config.js` 의 배경음악 주소에 붙은 `?v=` 해시를 갱신합니다. GitHub Pages 의 10분 캐시 때문에, 이걸 빼먹으면 사용자가 새로고침해도 예전 CSS·JS 가 보입니다(실제로 겪음).
- 수정이 끝나고 검증되면 **바로 커밋하고 `master` 에 푸시**합니다. 사용자가 배포 주소를 폰(사파리·카카오톡)으로 열어 직접 테스트하기 때문입니다. 푸시 후 GitHub Pages 반영까지 확인합니다.
- 커밋 작성자는 저장소 로컬 설정(김담영)을 따릅니다.
- 커밋 메시지는 한국어로 변경 요약을 씁니다.
